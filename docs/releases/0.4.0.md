# Chadex 0.4.0

Chadex 0.4.0 turns several runtime-only capabilities into a user-manageable local agent workspace. The release adds Agent Settings for project instructions and Skills, automatic bounded Project Memory context, and safety-gated Computer Use while simplifying the macOS sidebar around projects and the controls users actually need.

## Changes

- **Agent Settings** combines the currently selected project's Project Instructions and Skills in one workspace. `AGENTS.md` remains project-scoped and hierarchical; Skills remain reusable procedures with their own discovery, trust, revision, and execution contracts.
- A missing root `AGENTS.md` can now be created before ChatGPT connects. Chadex writes only inside the selected local project, uses atomic create-new behavior, and fails closed rather than overwriting an existing file.
- Skills can be discovered and managed from Agent Settings. Definitions remain lazy-loaded, project/configured/managed sources remain distinguishable, and revision fences prevent stale definitions from being used as current.
- **Project Memory** is no longer a permanent sidebar destination. Authorized bootstrap Memory summaries are automatically projected when a coding task starts; detailed bodies remain lazy. Durable architecture, decisions, and workflows may be persisted for later sessions, while transient logs, generated paths, secrets, and speculation are explicitly excluded from normal closeout guidance. Manual inspection remains available through the project's advanced **Memory Inspector…** action.
- **Computer Use** adds read-only UI observation and semantic control actions with three safety states: Read-only, Ask before control, and Allow this session. The macOS UI separates an offline-configurable Read-only / Ask default policy from session-only Allow/Stop controls.
- Computer control is gated independently at Helper ingress, preserves approval and audit evidence, blocks protected/password/authentication surfaces, rejects stale UI identities, and treats uncertain post-dispatch failures as `outcome_unknown` requiring re-observation rather than blind replay.
- Computer acceptance covers launch → activate → inspect → input → scroll → press → screenshot → semantic verification, plus permission denial, stale identities, protected surfaces, multi-monitor behavior, Runner disconnect/restart, and Windows parity fixtures.
- macOS nested runtime signing now uses stable identifiers such as `app.chadex.runtime.runner`. Development/Developer ID signing can preserve stable TCC identity; the free ad-hoc public build intentionally remains rebuild-sensitive and may require Computer permissions to be granted again after an update.
- The macOS sidebar is simplified to projects plus **Agent Settings**, **Computer Use**, Activity, Guide, and Settings instead of expanding every project into five feature subpages.
- Windows product metadata is synchronized to 0.4.0. The synthetic upgrade fixture now exercises 0.3.3 → 0.4.0 using the same production binaries; this validates installer migration rather than historical application compatibility.

## Validation

The final v0.4.0 release candidate is required to pass the clean `./scripts/release_check.sh` source gate, focused Project Memory and Skill execution regressions, the Computer acceptance suite, release tooling checks, and a fresh release-profile macOS app build. The tag workflow repeats the public-history / secret scan, source gate, free ARM64 package build, mounted-DMG smoke, signatures/resources checks, and SHA-256 generation before GitHub Release publication.

AP3.5/AP3.5.1 acceptance before the version bump included 74/74 Swift tests, 16/16 Project Memory regression tests, a real Skill resource-execution E2E, Computer acceptance at 68/68, offline `AGENTS.md` create/no-overwrite coverage, and clean release-profile app packaging. Final release evidence is refreshed again after version metadata, documentation, Graphify, and Obsidian synchronization are complete.

## Distribution boundaries

The public `Free Release` workflow for v0.4.0 publishes the macOS 14+ Apple Silicon DMG and SHA-256 sidecar. It uses Hardened Runtime with ad-hoc signing and is not notarized; first launch may require **System Settings → Privacy & Security → Open Anyway**.

The ad-hoc public package cannot preserve a stable macOS TCC code identity across rebuilds. Users who enable Computer Use may therefore need to grant Screen Recording or Accessibility again after installing an update. Chadex reports this package identity as rebuild-sensitive rather than claiming permissions will survive an update.

Windows W5 / Computer parity work is present in the release tree and CI can produce an unsigned installer candidate for validation, but `.github/workflows/release.yml` does not publish that Windows candidate as a public v0.4.0 release asset. Windows should therefore not be described as a signed/public binary release from this tag.

Computer Use never broadens the selected-project filesystem boundary or bypasses approval/sensitive-content protections. `Allow this session` is reset when a new tunnel session begins.
