# Chadex 0.6.5

Chadex 0.6.5 stops Computer Use from leaving Chromium browsers slow and makes ChatGPT reach for Computer Use when a task needs the desktop. Public distribution remains the macOS Apple Silicon DMG; the Windows application remains an unsigned CI validation candidate.

## Changes

- **Web accessibility is switched back off when idle (macOS)**: since 0.6.0, observing a Chromium/Electron app set `AXManualAccessibility` and never reset it, so a browser running a long ChatGPT conversation (reported with Brave) stayed sluggish after Computer Use looked at it once. Chadex now reads the value before its first write and never switches off an app that already had it on; for the rest it switches it back off after 120 s without an observation that needs it, or when the runtime exits. The next observation switches it on again and waits for the page tree.
- **When to use Computer Use**: the `computer_observe` and `computer_control` descriptions now say they are for seeing and operating desktop apps, System Settings, browser pages and running builds, and tell the model to stop and ask instead of retrying when the user keeps changing the foreground window.

## Known limitations

The 0.6.0 limitations still apply. See `docs/releases/0.6.0.md`. That Chromium honours `AXManualAccessibility = false` follows from the Chromium/Electron implementation; on the maintainer's Mac the value was not read back directly. A preview build reports "Update Chadex to v0.6.4" because its version is higher than the last public release; the button should not be used on preview builds.

## Validation

- `cargo test -p chadex-runtime-computer` (172 passed, 5 new lease tests), `-p chadex-runtime-tool-contracts` (141 passed), `-p chadex-runtime-engine --lib` (2754 passed).
- A `workflow_dispatch` build on `macos-26` (run 38074983512) was installed on a physical Mac: ChatGPT used `computer_control` on its own to finish a 14-minute Brave task without interruption, and the maintainer reported ChatGPT in Brave was not sluggish afterwards.
- The tag's Free Release workflow runs the source release gate, the ARM64 DMG package gate and the SDK check.

## Distribution boundary

`.github/workflows/release.yml` remains the free macOS distribution path and does not publish the Windows candidate. Publishing Windows assets, enabling a Windows updater or changing the signing policy requires a separate explicit release decision.
