# Chadex 0.6.0 (draft)

Chadex 0.6.0 is a design, Computer Use and connection-hardening release. It is expected to bring the second-generation visual design to macOS and Windows, add a permission card, a cursor overlay and Chromium web accessibility to Computer Use, validate the Tunnel ID before saving, disable the local shared-key login, and tighten test and CI reliability. Public distribution remains the macOS Apple Silicon DMG; the Windows application remains an unsigned CI validation candidate.

This is a draft. The listed changes are the PRs expected to be included (jimmynycuee/Chadex); none have been merged yet, so the list and the validation section must be updated at release time.

## Expected changes

### Design v2

- **Windows (#1)**: Fluent type scale, connection circuit, activity timeline, Mica backdrop, dark as the default appearance.
- **macOS (#2)**: Liquid Glass sidebar, connection circuit, activity timeline, dark as the default appearance, and a fix so the app builds on the macOS 15 SDK used by CI.

### Computer Use

- **Permission card (#4)**: the Computer Use page shows Accessibility and Screen Recording status in a card, with granted permissions in green.
- **Window activation (#5)**: the tool descriptions only call `activate_window` before key or pointer actions.
- **Timing log (#6)**: every Computer Use action records its elapsed time.
- **Cursor overlay on macOS (#8)**: a non-activating, click-through cursor window shows where the model is about to act. It is on by default and has a toggle on the Computer Use page. Windows has a design only.
- **Chromium/Electron web accessibility (#9)**: sets `AXManualAccessibility` on detected Chromium/Electron apps (never on sensitive surfaces; `CHADEX_COMPUTER_WEB_ACCESSIBILITY=off` disables it), adds `root_element_id` subtree queries and a deeper `find_elements`.
- **Sensitive pages (#15)**: sign-in pages and password managers are treated as sensitive.

### Connection and security

- **Tunnel ID validation (#14)**: the Tunnel ID is checked with the helper's rule before it is saved. This fixes `credential_push` failing at startup and the connection staying at `unconfigured`.
- **Local shared-key login disabled (#17)**: the helper starts the local server with `WEBCODEX_SHARED_KEY_ENABLED=false`, which also covers existing installs without rewriting `webcodex.env`.
- **Planned, PR not opened yet** (branch `fix/runtime-cors-host`): runtime CORS and Host allowlist, and anonymous access forced off. Remove this item if it does not land.

### Test, CI and docs

- **W5 smoke (#3)**: the smoke run prints unexpected exceptions, and the `process_inventory` time limit goes from 15 to 60 s.
- **Runtime tests (#7)**: the environment-variable races in runtime tests are fixed at the root.
- **Windows core gate (#11)**: a `job_manager` test race is fixed, and the local Windows shell open time limit is 90 s.
- **CI triggers (#13)**: push builds run only on `main`.
- **W5 docs (#12)**: readiness docs updated to the v0.5.0 baseline.

## Upgrade notes and behavior changes

- **Shared-key profiles stop working (#17).** If you manually created a `webcodex connect` profile against the local server with a shared key, it no longer works after upgrading. Chadex itself does not use shared keys. A server already running keeps the old setting until it restarts.
- **Sensitive screens reject unrooted `find_elements` (#9).** On new macOS runners, `find_elements` without a root now returns `permission_denied` on a sensitive screen; before, the server-side filter searched it.
- **Web sign-in pages are blocked (#9 with #15).** Once #9 exposes web content, a page whose title looks like a sign-in or password page is treated as sensitive and the model cannot operate it. The match is deliberately broad, so titles that only mention passwords (for example a file named `password-policy.md`) and some CJK words such as 密碼學 are blocked too. You can operate those screens yourself.
- **Tunnel IDs the helper rejected are now refused at save time (#14).** Only values the helper already rejected are newly refused.

## Known limitations

- **macOS design v2 is pending validation.** It has been reviewed by AI reviewers only. There is no external design validation and no user acceptance on a physical machine yet, so it must not be described as award-level or externally validated.
- **Windows is verified in CI only.** There has been no physical-machine testing of the Windows design v2 or any other Windows change.
- **Cursor overlay (#8) is not verified on a real Mac.** Exclusion from screenshots and recordings (Cmd+Shift+3/4/5, QuickTime, screen share, `computer_observe`) on macOS 14/15/26 has not been tested. Appearance, multi-display, Spaces/full screen, reduce motion and latency are also untested. The screenshot exclusion test must pass before release.
- **Web accessibility (#9) is not verified on a real Mac.** Whether Chrome, Edge, Brave or Arc accept `AXManualAccessibility`, budgets on long pages, auto-disable recovery and secure fields are untested.
- The 0.5.0 limitations still apply: a ChatGPT session with the bootstrap token still has full permissions, hidden `$` shares cannot be Skill sources, and removing a Skill affects every project on the local runtime.

## Validation

To be filled in at release time. Required before release:

- `release_check.sh` exit 0 and full CI success on the release commit.
- User acceptance of `dist/Chadex.app`.
- #8: real-machine test that the cursor overlay is excluded from screenshots.
- #9: check that Chrome and Brave accept `AXManualAccessibility` (design L1).
- #14: a fresh launch shows `credential_push ok` in the diagnostics export.
- #17: after upgrading, local connect, runner online, Skills and Project Memory work.

The Windows CI historical-upgrade gate now builds the public `v0.5.0` tag and upgrades it to the 0.6.0 candidate, and the synthetic installer-migration fixture models `0.5.0 -> 0.6.0`.

## Distribution boundary

`.github/workflows/release.yml` remains the free macOS distribution path and does not publish the Windows candidate. Publishing Windows assets, enabling a Windows updater or changing the signing policy requires a separate explicit release decision.
