# Chadex 0.3.0

Chadex 0.3.0 focuses on long-running task reliability and host-progress observability without changing the core project-permission or updater trust boundaries.

## Long-running work

- **Longer model-facing observation window.** Long-job observation now uses a bounded 60-second model-facing wait instead of the older short slicing behavior, reducing unnecessary model re-entry while preserving event-driven terminal/failure wakeups.
- **No replay on timeout/truncation.** A durable job remains the same execution across observation timeout or truncated output; callers resume/observe the existing job rather than launching a duplicate.
- **Terminal handoff observability.** Chadex records bounded, principal/window-scoped correlation between a meaningful terminal tool response and the next meaningful host/model request. This is diagnostic evidence only: it does not autonomously wake the host or replay completed work.
- **Fail-closed continuity.** Overlapping or ambiguous requests do not claim serial terminal-follow-up continuity, and non-meaningful runtime-status calls do not consume the pending terminal anchor.

## Validation evidence

The v0.3.0 runtime direction was exercised with paired Chadex/WebCodex benchmarks and a dedicated endurance workflow:

- all Phase20C formal paired runs completed successfully with preserved correctness and no duplicate durable-job execution;
- a formal Phase20D repository endurance run completed in about 14 minutes of runner time on Chadex;
- the endurance run included one ~5-minute bursty durable validation and one ~6-minute silent durable validation;
- both long jobs were started exactly once and reached terminal success;
- an observation timeout/truncated-output event during the release validation resumed the same job instead of restarting it;
- the previously observed intermittent `no next action after local terminal` failure did not reproduce in the formal Phase20C/20D validation runs.

These results support release readiness but do not claim that an intermittent host-side stall is mathematically impossible. The new handoff evidence exists specifically so a future recurrence can be diagnosed without weakening validation or replaying work.

## Updater / compatibility

- The existing stable GitHub Release updater contract is unchanged: Chadex verifies the DMG checksum, bundle identifier, version, Apple Silicon architecture, and macOS signature before staging an update.
- The external installer still waits for normal helper/runtime shutdown, keeps the previous app as a temporary backup, and rolls back if the new version fails launch verification.
- Users on 0.2.x can update directly to 0.3.0; no data migration is required.

## Distribution

The public free macOS release remains Apple Silicon (`arm64`), Hardened Runtime, ad-hoc signed, and not notarized. First launch may therefore require **System Settings → Privacy & Security → Open Anyway**.
