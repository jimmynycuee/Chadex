# Chadex 0.7.0

Chadex 0.7.0 adds Plan Mode and Goal Mode, and shows when ChatGPT is operating the Mac through Computer Use. Public distribution remains the macOS Apple Silicon DMG; the Windows application remains an unsigned CI validation candidate.

## Changes

- **Plan Mode**: ChatGPT plans in a backend-enforced read-only mode (every write, shell and job tool is refused while a plan is open). Each plan revision is immutable and hashed. The user reviews it in the app's Plan & Goal panel (diff against the previous revision, request changes, approve). Only the Chadex app can approve; the model cannot. After approval, ChatGPT is told in the same reply (`plan_wait_approval`) and implements the plan directly, then runs its acceptance checks.
- **Goal Mode**: ChatGPT sends a goal with objective and acceptance commands (exit 0 means done); the user starts it in the app, and the model can never start one itself. When starting, the user picks a mode:
  - **Codex**: Chadex runs Codex CLI in the background until the checks pass. This uses the user's Codex tokens, which the app says next to the button. ChatGPT can be closed.
  - **ChatGPT**: ChatGPT edits the Goal's worktree in the conversation and calls `goal_check`; Chadex runs the acceptance checks each round until they pass. No Codex tokens. A run with no turn for 30 minutes pauses and resumes on the next check.
  Work happens in an isolated worktree and ends on a branch `chadex/goal/<id>`. Nothing is merged, pushed or deployed. Acceptance runs sandboxed. Runs have budgets, pause, cancel and an emergency stop, and survive restarts. A macOS notification announces a finished Goal or a request waiting for Start. A Goal needs a Git commit; the app says so and shows the commit commands.
- **Computer Use activity notice**: while ChatGPT operates the Mac, a notice in the top-right corner and the menu bar icon say so, with the time since the last action. After 15 s without an action the notice says ChatGPT has paused, then hides. The notice takes no clicks, is kept out of screen capture and is hidden from `list_windows`; stop from the menu bar.
- **Skills**: `chadex-plan` and `chadex-goal` Skills for ChatGPT (`dist/skills/` in a source build) describe both flows; upload them in ChatGPT to use `@chadex-plan` / `@chadex-goal`.

## Known limitations

The 0.6.0 limitations still apply. See `docs/releases/0.6.0.md`. Plan Mode and Goal Mode were validated end to end against an isolated helper, server and runner, with a fake and with a real Codex CLI, but not yet through the ChatGPT web app and a real tunnel. ChatGPT cannot be pushed to: it learns about approval only while it waits in `plan_wait_approval` (at most 45 s per call), and about a Codex-mode Goal only when it asks. The activity notice infers "paused" from 15 s without an action, since ChatGPT never says it is done. Known design gaps are listed in `docs/PLAN_GOAL_MODE.md` (one operator per Mac, no revalidation of the dispatch principal after it is recorded). A preview build offers "Update Chadex" because of the version compare; do not use it on preview builds.

## Validation

- `cargo test -p chadex-runtime-engine --lib` (2790 passed), `-p chadex-runtime-store` (187), `-p chadex-runtime-tool-contracts` (141), `-p chadex-runtime-tool-runtime-contracts` (96); clippy clean.
- `swift test`: 261 executed, 1 skipped, 0 failures (5 new activity-notice tests).
- `scripts/e2e_plan_goal.py` with a fake agent: Plan Mode refuses all writes; an approved plan returns `approved` to ChatGPT, which cannot start a Goal; Codex-mode and direct Goals succeed in iteration 2 on a re-verified branch; a ChatGPT-mode Goal fails round 1, ChatGPT fixes the worktree, round 2 passes, and the user's checkout is untouched; a repository without commits cannot start a Goal. A real Codex CLI run and a restart/resume run passed earlier on the same branch.
- The tag's Free Release workflow runs the source release gate, the ARM64 DMG package gate and the SDK check.

## Distribution boundary

`.github/workflows/release.yml` remains the free macOS distribution path and does not publish the Windows candidate. Publishing Windows assets, enabling a Windows updater or changing the signing policy requires a separate explicit release decision.
